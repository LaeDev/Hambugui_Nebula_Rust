> **Workflow:** Execute task-by-task. Steps use checkbox (`- [ ]`) syntax. Read `docs/plans/DESIGN.md` before any GUI task. Read the upstream TypeScript behaviour notes in this file before porting a module: the JSON output must stay compatible in shape (same keys, same values, same module order) with upstream Nebula (`dscalzi/Nebula@7ffc978`) plus the Hambugui hardening patch (SHA-256 alongside MD5, clean relative paths, symlink rejection). >
> **Reference source:** `src/` was deleted from the worktree in Task 0. The upstream TypeScript tree is extracted at `C:\Users\Lae_\AppData\Local\Temp\nebula-qa\upstream-ts\src\` and is also available with `git show 7ffc978:src/<path>` from the worktree. The hardening patch is `H:\HambuguiLauncherRust\docs\baseline\nebula-hardening.patch.gz` (`gzip -d -c`). **Every porting task must read the corresponding TS file before writing Rust.**

**Goal:** Replace the Node/TypeScript Nebula CLI with a single Rust binary `nebula` that offers the same CLI commands plus a Slint GUI (3:4 portrait), emits distribution.json files that Helios Launcher and Hambugui Launcher (`H:\HambuguiLauncherRust`, crate `hambugui-distribution`) both accept, and removes every Node artifact from the repository.

**Architecture:** Cargo workspace with two crates. `crates/nebula-core` is a pure library (no UI): config, version/maven parsing, file-structure layout, module scanning (files/libraries/forge mods/fabric mods), Forge (FG2/FG3) and Fabric resolvers, CurseForge import, distribution generation, JSON schema generation, and launcher-contract validation. `crates/nebula` is the binary: `clap` CLI subcommands mirroring upstream, and a `gui` subcommand (default when launched with no arguments) built with Slint 1.17.1 (same pinned version/toolchain as Hambugui Launcher). Long operations run on a worker thread and report through the `log` crate; the GUI installs a `log::Log` sink that forwards records into the UI.

**Tech Stack:** Rust 1.97.0 (pinned via `rust-toolchain.toml`, edition 2024), clap 4.6, serde/serde_json, schemars 1.2, reqwest 0.13 (blocking, rustls), zip 8.x, toml 1.x, globset 0.4, md-5 0.11 + sha2 0.11, dotenvy 0.15, url 2.5, tempfile 3, slint 1.17.1 (=pinned) + slint-build, log 0.4 + env_logger 0.11. Java jars `Claritas.jar` and `PackXZExtract.jar` are embedded with `include_bytes!` and extracted to `<root>/work/java/` on demand.

**Compatibility contract (from `H:\HambuguiLauncherRust\docs\adr\0001-nebula-contract.md`, `crates/hambugui-distribution/src/*.rs`):**
- Every artifact object: `size` (u64), `url` (http/https), `MD5` (legacy) **and** `SHA256` (required by runtime), optional `path` that must be a clean relative path (no leading `/`, no `..`, no drive letter, no UNC, forward slashes only).
- Module `type` must be one of `Forge, ForgeHosted, Fabric, LiteLoader, Library, ForgeMod, LiteMod, FabricMod, File, VersionManifest`.
- Module ids without explicit `path` must be Maven coordinates `group:artifact:version[:classifier][@ext]` (runtime derives the path), except `VersionManifest` ids which may be a single safe segment.
- Server ids unique. `required` is a bool or `{ "value": bool, "def": bool }`.
- Runtime additionally demands HTTPS for every artifact URL. Nebula only warns on `http://` (local dev with `BASE_URL=http://localhost:8080/` must keep working), and `validate --strict` turns it into an error.

## Upstream behaviour notes (read before porting)

**Directory layout (`<root>` = `ROOT`):**
- `meta/distrometa.json`, `schemas/DistroMetaSchema.schema.json`, `schemas/ServerMetaSchema.schema.json`
- `servers/<id>-<mc>/` with `servermeta.json`, `files/`, `libraries/`, `forgemods/{required,optionalon,optionaloff}/` (Forge servers), `fabricmods/{required,optionalon,optionaloff}/` (Fabric servers), optional icon `*.png|*.jpg`
- `repo/lib/<maven path>` shared library cache (also served: URL = `BASE_URL + repo/lib/<maven path>`)
- `repo/versions/<mc>-<forge|fabric>-<loader>/<same>.json` version manifests (served at `BASE_URL + repo/versions/...`)
- `cache/forge/<artifactVersion>/` installer output cache; `temp/` pack.xz work dir; `work/java/` (new) extracted jars; `<server>/claritasWork/` Claritas scratch
- `modpacks/curseforge/<zip>` CurseForge input

**URL building:** `Url::parse(base_url)` where base_url is normalised to end with `/`; then `base.join("servers/<id>/files/<rel>")`. Segments are percent-encoded by the url crate exactly like WHATWG URL in Node. Upstream did not force a trailing slash (a `https://host/dist` base silently dropped `dist`); we do force it and document it.

**Server directory id regex:** `(.+-(.+)$)` → `id` = full dir name, `minecraftVersion` = text after the last `-`.

**Module id formats:**
- Mods: `<group>:<modId>:<version>@jar`; default group `generated.forgemod` / `generated.fabricmod`; libraries `generated.library:<name>:<version>@jar` where name/version come from the crude inference regex `/(.+?)-(.+).[jJ][aA][rR]/` — **unanchored, and the `.` before `jar` is unescaped (any single character)**. Port as: find the first `-`; if the remainder contains any character followed by `jar` (case-insensitive) at any position, split there (`name` = text before the first `-`, `version` = text between the `-` and that `.jar`-like match, lazily: the regex's `(.+)` is greedy so it takes the **last** match); otherwise `(stem, "0.0.0")` where stem is the text before the **last** `.`. Test: `foo-1.0.jar.bak` → `("foo", "1.0")`; `foo-1.0.jar` → `("foo","1.0")`; `foo.jar` → `("foo","0.0.0")`.
- FG2 libraries: `group:artifact:version[:classifier]@<ext>` with ext `jar` or `jar.pack.xz`.
- FG3 generated files: `group:artifact:version[:classifier]` (no `@ext`). FG3 manifest libraries **with installer**: `entry.name` verbatim (`ForgeGradle3.resolver.ts:558`). FG3 **without installer** (1.12 > 2847, `processWithoutInstaller`): `group:artifact:version[:classifier]@jar` re-derived through `MavenId` (lines 723-754); the `net.minecraftforge:forge:` entry is skipped; the root module is `net.minecraftforge:forge:<av>:universal` (`ForgeHosted`, name `Minecraft Forge`) with the VersionManifest as first sub-module.
- Fabric libraries: `lib.name` verbatim; Fabric version manifest id `<mc>-fabric-<loader>`; Forge version manifest id `<mc>-<forge>` (= artifactVersion).

**Server spec assembly (`Server.struct.ts:130-240`):** module order is: Forge root module (with its subModules), Forge mods, Fabric root module, Fabric mods, libraries, files. Icon: if `serverMeta.meta.icon` parses as a URL use it verbatim; else scan the server directory (non-recursive) for files ending in `.png`/`.jpg` case-insensitively and take the **last** match in directory order (upstream loop does not break; we iterate sorted names so "last" is deterministic), URL = `servers/<dir>/<file>`; none → warn and emit `"icon": null` (always serialised). Server fields: `id` = dir name, `name/description/version/address/discord/mainServer/autoconnect/javaOptions` from `servermeta.meta`, `minecraftVersion` = text after the last `-`. `Distribution.version` is the hardcoded string `"1.0.0"` (`Distribution.struct.ts:55`); `rss` and optional `discord` come from `distrometa.meta`.

**Default `servermeta.json` (`ServerMeta.ts:getDefaultServerMeta`)**: `version: options.version ?? "1.0.0"`, `name: "<id> (Minecraft <mc>)"`, `description: "<id> Running Minecraft <mc>"` (+ ` (Forge v<x>)` / ` (Fabric v<x>)`), `icon: "How to set the server icon: https://github.com/dscalzi/Nebula#setting-the-server-icon"`, `address: "localhost:25565"`, discord placeholders `"<FILL IN OR REMOVE DISCORD OBJECT>"` ×3, `mainServer: false`, `autoconnect: false`, `forge`/`fabric: { version }` when given, `untrackedFiles: []`.

**Version manifest on disk:** Forge without-installer writes `repo/versions/<mc>-forge-<fv>/<same>.json` with **4-space indentation** (`writeJson(..., { spaces: 4 })`, `ForgeGradle3.resolver.ts:641`) and hashes that file; Forge with-installer copies the installer's manifest verbatim; Fabric writes compact JSON (`JSON.stringify(manifest)`, `Fabric.resolver.ts:53`) and hashes that. Indentation is load-bearing for the digests.

**FG3 `processLibraries`:** only manifest libraries whose `downloads.artifact.url` is non-empty are emitted (`if (artifact.url)`, line 546) — this is how Forge's own entry is skipped; each must exist under `<installer output>/libraries/<downloads.artifact.path>` or the build fails.

**FG2 `determineExtension`:** returns `jar` immediately when `lib.url` is null (Mojang library); downloads use `lib.url || MOJANG_MAVEN`.

**Claritas failures are non-fatal** (`ClaritasWrapper`: non-zero exit → result `undefined`, logged; `ForgeMod*` then falls back to crude/metadata values).

## NeoForge support (new feature, requested 2026-09-10; no upstream equivalent)

Upstream Nebula has no NeoForge support and `helios-distribution-types@1.3.0` (latest, 2023-12) defines no NeoForge module type, so Nebula defines two new types: **`NeoForge`** (loader root, lives in the common libraries root like `Forge`/`ForgeHosted`) and **`NeoForgeMod`** (instance mods, default extension `jar`, default group `generated.neoforgemod`). Hambugui's parser rejects unknown types today, so Task 8 ships and verifies a launcher patch (`docs/launcher/hambugui-neoforge.patch`). Helios does not support NeoForge at all; `validate` reports one warning per distribution when NeoForge types are present.

- **Scope:** Minecraft 1.20.2+ (`net.neoforged:neoforge`, versions `A.B.C[-beta]` and, for year-based Minecraft, `A.B.C.D`). Legacy NeoForge for 1.20.1 (`net.neoforged:forge`, `1.20.1-47.1.x`) is **not** supported (use Forge 47.x).
- **Version prefix rule:** MC `1.A.B` → prefix `A.B.` (`B` = 0 when the patch is absent: `1.21` → `21.0.`); MC `A.B` with `A ≥ 26` (year-based) → `A.B.`. `version::is_neoforge_supported(mc)` = `(major==1 && minor==20 && patch>=2) || (major==1 && minor>=21) || major>=26`.
- **Version list:** `GET https://maven.neoforged.net/api/maven/versions/releases/net/neoforged/neoforge` → `{ "isSnapshot": bool, "versions": [String] }` (ascending order, but never rely on it). Keep entries that start with the prefix and whose remainder is digits/dots optionally followed by `-beta`; ignore everything else (e.g. `0.25w14craftmine.3-beta`). `latest` = max by numeric components (the `-beta` suffix is ignored for ordering); `recommended` = max among entries without `-beta`, falling back to `latest` with a warning. `remote::get_neoforge_versions()`, `remote::get_promoted_neoforge_version(mc, promotion) -> Result<String>`; constants `NEOFORGE_MAVEN = "https://maven.neoforged.net/releases/"`, `NEOFORGE_VERSIONS_API`.
- **Installer:** `NEOFORGE_MAVEN + net/neoforged/neoforge/<v>/neoforge-<v>-installer.jar`, stored in `repo/lib` at the Maven path of `net.neoforged:neoforge:<v>:installer`. Run exactly like the Forge divergence steps (a)–(d) with cache dir `cache/neoforge/<v>` (`Root::neoforge_cache_dir(v)`) and `--installClient <dir>` (NeoForge installers honour it headlessly; keep the same GUI fallback code path). Manifest detection is data-driven: after the run, `<cache>/versions/` must contain exactly one `<name>/<name>.json`; otherwise treat as failure (delete cache dir, error naming the directory).
- **Version manifest module:** copy that file to `repo/versions/<mc>-neoforge-<v>/<same>.json`; module id `<mc>-neoforge-<v>`, name `NeoForge (version.json)`, type `VersionManifest`, url `repo/versions/...`.
- **Libraries (data-driven, no hard-coded matrix):** parse the manifest as `VersionManifestFg3` (same shape: `libraries[].name`, `downloads.artifact.{path,url,sha1,size}`). For each library in manifest order: if `url` is non-empty → ensure the file exists in `repo/lib/<path>` with matching SHA-1 (download otherwise); if `url` is empty → the installer generated it: copy `<cache>/libraries/<path>` to `repo/lib/<path>` (error if missing). Module: id = `name` verbatim, type `Library`, name `NeoForge (<artifact>)`, url `repo/lib/<path>` (built from the `path` string, not from the Maven id), no `classpath` field (all NeoForge libraries stay on the classpath; the version manifest's JVM arguments own the module path).
- **Root module:** the manifest library whose `name` starts with `net.neoforged:neoforge:` and ends with `:universal` becomes the root with type `NeoForge`, name `NeoForge`; `subModules` = `[VersionManifest, every other library module in manifest order]`. Error if no universal entry exists.
- **Findings from the real run (Task 3, NeoForge 21.1.250, 2026-09-10) — these supersede the two bullets above where they differ:**
  - The installer argument must be written **attached**: `--installClient=<dir>`. Both Forge and NeoForge `SimpleInstaller` declare the option with joptsimple `withOptionalArg()`, so a space-separated directory is ignored and NeoForge would install into the user's real `.minecraft`. (`resolver/forge.rs` documents this; never "clean it up".)
  - The installer writes two `versions/` directories (the loader profile and the patched vanilla one); manifest discovery therefore selects the profile that declares `inheritsFrom`.
  - The NeoForge manifest lists 47 libraries, all with real URLs, and **no** `:universal` entry. FancyModLoader resolves four artifacts under `-DlibraryDirectory` that the manifest never lists: `net.neoforged:neoforge:<v>:universal`, `:client`, `net.minecraft:client:<mc>-<neoform>:srg`, `:extra` (versions read from the manifest's `--fml.neoForgeVersion` / `--fml.mcVersion` / `--fml.neoFormVersion` arguments). They are copied out of the installer output into `repo/lib`, emitted with `classpath: false` (FG3 parity for universal/client/srg/extra), and the `:universal` one is the `NeoForge` root module. `slim` is intentionally not shipped.
- **Metadata & layout:** `servermeta.neoforge: { version }` (mutually exclusive with `forge`/`fabric`; `create_server` errors if two loaders are given); default description suffix ` (NeoForge v<x>)`; server dir `neoforgemods/{required,optionalon,optionaloff}` (`ServerDir::neoforgemods_dir()`); `untrackedFiles[].appliesTo` accepts `neoforgemods`.
- **Scanner:** NeoForge mods use the 1.13+ Forge flavour (`scan/forgemod.rs`) with the flavour passed explicitly (never derived from the MC version, which may be `26.x`): try `META-INF/neoforge.mods.toml` first, then `META-INF/mods.toml`; Claritas is still invoked with library type `FORGE` (it may return nothing for NeoForge annotations → fallbacks apply); emitted type `NeoForgeMod`, untracked rel path `<namespace>/<file>`.
- **Server spec module order:** Forge root, Forge mods, NeoForge root, NeoForge mods, Fabric root, Fabric mods, libraries, files.
- **CLI:** `generate server <id> <mc> --neoforge <v|latest|recommended>` (conflicts with `--forge`/`--fabric`), `latest-neoforge <mc>`, `recommended-neoforge <mc>`. **GUI:** loader selector 없음 / Forge / NeoForge / Fabric; the 최신/권장 lookup buttons work for NeoForge.
- **Validation:** `NeoForge`/`NeoForgeMod` are accepted types; when any is present add one Warning at `servers[i]`: `NeoForge 모듈은 Hambugui 런처에 NeoForge 파서 패치(docs/launcher/hambugui-neoforge.patch)가 필요하고 Helios는 지원하지 않습니다`.
- **Launcher patch (Task 8):** `docs/launcher/hambugui-neoforge.patch` against `H:\HambuguiLauncherRust` touching `crates/hambugui-distribution/src/schema.rs` (enum variants `NeoForge`, `NeoForgeMod`; `parse_module_type` arms), `src/normalize.rs` (`type_base`: `NeoForge` → `libraries`, `NeoForgeMod` → `mods`; `default_extension` jar), `src/lib.rs` (`resolve_artifact_path` root mapping), `tests/module_matrix.rs` (add both types). Verified by copying the crate (and `hambugui-domain`) into the scratchpad, applying the patch, and running `cargo test` there — the launcher repo itself is never modified by this project.

## Modpack import: CurseForge, Modrinth `.mrpack`, Prism/MultiMC instance export (new, requested 2026-09-10)

Prism Launcher exports an instance in three formats and Nebula must accept all of them through ONE auto-detecting importer (`crates/nebula-core/src/import.rs`; the existing `curseforge.rs` becomes its CurseForge branch):

| Format | Detection (zip entry) | Loader source | Files |
|---|---|---|---|
| CurseForge pack (`.zip`) | `manifest.json` | `minecraft.modLoaders[].id`: `forge-<v>`, `neoforge-<v>` (Prism writes `neoforge-1.20.1-<v>` for 1.20.1 → unsupported, error), `fabric-<v>`, `quilt-<v>` (unsupported → error) | `files[]` via CurseForge API (existing flow), `overrides/` → `files/` |
| Modrinth pack (`.mrpack`) | `modrinth.index.json` | `dependencies`: `minecraft`, `forge`, `neoforge`, `fabric-loader`, `quilt-loader` (unsupported → error) | `files[]`: `path` (relative to the game dir), `downloads[]` (take the first URL), `hashes.sha1` / `hashes.sha512` (verify sha1 after download; sha512 optional), `fileSize`, `env.client` ∈ `required` \| `optional` \| `unsupported` (skip `unsupported`; `optional` → `optionalon`; missing → required). `overrides/` then `client-overrides/` (later wins) are extracted; `server-overrides/` is ignored. |
| Prism/MultiMC instance (`.zip`) | `mmc-pack.json` | `components[]` by `uid`: `net.minecraft` (version), `net.minecraftforge`, `net.neoforged`, `net.fabricmc.fabric-loader`, `org.quiltmc.quilt-loader` (unsupported → error) | game dir is `.minecraft/` if present else `minecraft/` (Prism's `gameRoot()` rule); `mods/*.jar` → `<loader>mods/required/` (`*.jar.disabled` → `optionaloff/` with the `.disabled` suffix removed), everything else under the game dir except `mods/`, `logs/`, `crash-reports/`, `saves/`, `screenshots/`, `.fabric/`, `usercache.json`, `usernamecache.json`, `options.txt`? — no: keep `options.txt` (it is a config users ship); exclude only `logs/`, `crash-reports/`, `saves/`, `screenshots/`, `.fabric/`, `.mixin.out/`, `usercache.json`, `usernamecache.json`, `*.log` → `files/<same relative path>` |

Rules for every format: zip-slip safety through `paths::clean_relative` on each entry name; `mods/` path segment routing decides mod vs file (`.jar` under `mods/` → mod container; `.zip` under `resourcepacks/`/`shaderpacks/` stays a file); the server is created with `create_server(id, mc, opts)` using the detected loader and `version` from the pack (`manifest.version` / `versionId` / `instance.cfg` `name=` is only used for the default `servermeta.meta.name`); the importer returns `ImportReport { created: CreatedServer, format: ImportFormat, downloaded: usize, copied: usize, skipped_unsupported: usize, manual: Vec<ManualDownload> }`.
- Input location: `<root>/modpacks/` (any subfolder; `init root` creates `modpacks/curseforge` for compatibility and `modpacks/prism`), or an absolute path.
- CLI: `generate server-import <id> <file>` (auto-detect); `generate server-curseforge <id> <zipName>` stays as an alias that only accepts the CurseForge format. GUI import screen lists `modpacks/**/*.zip|*.mrpack` with the detected format label next to each file.
- `remote.rs` gains `download_to_verified(url, dest, expected_sha1: Option<&str>)`.
- Tests (offline): synthetic zips for all three formats built with the `zip` crate; mrpack test uses a local `file://`? — no: use a tiny in-process HTTP stub? Keep it simple: the mrpack test supplies `downloads` pointing at a `tempfile`-hosted path via a `DownloadFn` injected into the importer (`fn(url, dest) -> Result<()>`), defaulting to `remote::download_to_verified` in production. Assert the routing table above (required/optional/unsupported, disabled jars, excluded dirs, client-overrides precedence).

## Publishing targets: WebDAV (Synology/헤놀로지) and Google Drive (new, requested 2026-09-10)

Nebula gains a `publish` stage that uploads exactly the files a generated distribution references. Module `crates/nebula-core/src/publish/{mod.rs,webdav.rs,gdrive.rs}`.

- **Publish plan:** parse the generated `distribution.json` as `serde_json::Value`; collect every `artifact.url` and server `icon` that starts with `base_url`; `relative` = percent-decoded remainder; `local` = `<root>/<relative>` (must exist, else error listing missing files). Plus the distribution file itself as `<name>.json`. Deduplicate.
- **Change tracking:** `<root>/publish-state.json` maps `target-name → { relative → sha256 }`; with `--only-changed` (default true in the GUI) files whose SHA-256 matches are skipped.

**Untracked files:** `servermeta.untrackedFiles[].appliesTo` names the struct dir (`files`, `forgemods`, `fabricmods`, `libraries`); patterns are glob (minimatch semantics: `*` does not cross `/`; use `globset` with `literal_separator(true)`). }
