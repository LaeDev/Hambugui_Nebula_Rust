### 실행 시점에 대한 정정

작업 지시에서는 4단계(`g server New ... --forge recommended`)에서 인스톨러가 돌 것으로 예상했으나,
`cli.rs::generate_server`는 프로모션 버전 조회 후 `server::create_server`만 호출합니다.

**단, 정직하게 부기합니다**: `cli.rs::installer_gui_fallback()`은
`NEBULA_FORGE_GUI_FALLBACK != "0" && stdin().is_terminal()` 두 조건의 AND입니다.

것입니다. 따라서 "창이 열리지 않았다"는 관찰은 확실하지만, **둘 중 어느 가드가 작동했는지는 분리 검증하지
않았습니다.**

## Findings (결함)

### F-1 [Low] `cargo deny check bans`가 HEAD에서 실패 — 워크스페이스가 자기 정책 파일을 위반

**재현**

```
cd <snapshot>
cargo deny check licenses bans sources
# -> bans FAILED, licenses ok, sources ok   (exit 2)
```

**증거** (`17d-deny.log:977`)

```
error[wildcard]: found 1 wildcard dependency for crate 'nebula'
   ┌─ crates\nebula\Cargo.toml:14:15
   │
14 │ nebula-core = { path = "../nebula-core" }
   │               ━━━━━━━━━━━━━━━━━━━━━━━━━━━ wildcard dependency
```

**추정 원인**: `deny.toml`의 `[bans] wildcards = "deny"`가 켜져 있는데
`allow-wildcard-paths`가 설정돼 있지 않습니다. cargo-deny는 `version`이 없는 path 의존성을
와일드카드로 간주하므로, 워크스페이스 내부 크레이트 참조가 그대로 걸립니다(cargo-deny 0.20.2 기준).

**영향 범위**: `.github/workflows/ci.yml`은 `fmt` / `clippy` / `test`만 돌리고 cargo-deny는 실행하지
않으므로 **현재 CI는 녹색입니다**. 기능에는 전혀 영향이 없습니다. 다만 리포지터리가 통과할 수 없는
정책 파일을 함께 배포하고 있는 상태이므로, 나중에 이 게이트를 CI에 넣으면 즉시 빨간불이 됩니다.

**제안 수정 (택1, 모두 1줄)**
- `crates/nebula/Cargo.toml`: `nebula-core = { path = "../nebula-core", version = "1.0.0" }`
- 또는 `deny.toml`의 `[bans]`에 `allow-wildcard-paths = true` 추가

> 참고: 같은 실행에서 `multiple-versions = "warn"`에 의한 duplicate 경고가 26건 나오지만
> 정책상 warn이므로 실패 사유가 아닙니다. 대부분 Slint 1.17.1의 전이 의존성입니다.

## 결함은 아니지만 기록해 둘 관찰

### O-1 `New-1.20.1`의 `ForgeHosted` 루트가 `lowcodelanguage`

1.20.1/Forge 47의 루트 모듈 id가 `net.minecraftforge:forge:...:universal`이 아니라
`net.minecraftforge:lowcodelanguage:1.20.1-47.4.10`입니다. 처음에는 결함으로 의심했으나,
`resolver/fg3.rs::generated_files`의 주석("Order is load-bearing: the first entry becomes the
`ForgeHosted` root module")과 **업스트림 TypeScript 원본을 대조 확인**한 결과 동일했습니다.
업스트림 `ForgeGradle3.resolver.ts`도 1.17+에서 `fmlcore/javafmllanguage/mclanguage`를,
1.18+에서 `lowcodelanguage`를 각각 `unshift`하므로 최종적으로 `lowcodelanguage`가 배열 선두가 됩니다.
**충실한 포팅이며 하네스도 수용**했습니다. 다만 눈으로 읽을 때 오해를 부르기 쉬운 부분입니다.

### O-2 `Ancient-1.7.10`에 `VersionManifest` 모듈이 없음

하네스 히스토그램의 `VersionManifest=4`는 서버 5개 중 4개라는 뜻이며, FG2(1.7.10) 서버만 없습니다.
업스트림 `ForgeGradle2.resolver.ts`가 버전 매니페스트를 **jar 내부에서**
읽기 때문(`getVersionManifestFromJar`)이며, 별도 매니페스트 모듈을 만들지 않는 것이 정상입니다.
`<ROOT>/repo/versions`에도 1.7.10 항목이 없는 것과 일관됩니다.

### O-3 `publish` 2회차가 `distribution.json`은 항상 재업로드

작업 지시의 "2회차는 전부 skip" 기대와 달리 `uploaded 1, skipped 134`가 나옵니다.
`publish/mod.rs:261`의 주석대로 인덱스는 `only_changed` 검사 밖에서 **항상 마지막에** 업로드됩니다
("so a launcher never sees a manifest pointing at files that are not there yet").
의도된 설계이며, 실제 콘텐츠 파일 134개는 전부 정상적으로 skip되었습니다.
