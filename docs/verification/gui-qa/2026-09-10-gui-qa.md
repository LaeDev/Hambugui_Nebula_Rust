# Nebula GUI (Slint) 실제 구동 QA — 2026-09-10

실제로 빌드한 `nebula.exe gui`를 이 Windows 머신에서 띄우고, Windows UI Automation
(`System.Windows.Automation`)으로 접근성 트리를 통해 조작한 결과다. 모든 판정은
실행 중인 창에서 읽은 값이거나 디스크에 남은 파일이며, 추정으로 채운 항목은 없다.
확인하지 못한 것은 §7 "검증하지 못한 것"에 그대로 적었다.

`먼저 배포본을 생성하세요`다. 원인+해결을 말하라는 §5 지침에는 더 잘 맞으므로

### D1 — 서버 스캔이 실패하면 목록이 통째로 비고, 화면은 "서버가 없다"고 말한다 · **높음**

`crates/nebula/src/gui/mod.rs:934-942`

```rust
let summaries = match server::list_servers(root) {
    Ok(summaries) => summaries,
    Err(error) => {
        log::error!("서버 목록을 읽지 못했습니다: {error}");
        return (Vec::new(), Vec::new());      // ← 빈 목록으로 대체된다
    }
};
```

재현: `servers\<아무거나>\servermeta.json`을 파서가 거부하도록 만든다(UTF-8 BOM만
붙여도 충분하다 — `serde_json`은 BOM을 건너뛰지 못한다). `서버` 페이지에서
`새로 고침`.

관찰: 디스크에 서버 디렉터리가 9개 있는데 카드 부제는 `0개`, 본문은 빈 상태
`아직 서버가 없습니다 / 새 서버를 만들거나 모드팩을 가져오세요.` 토스트도 콜아웃도
없다. 유일한 신호는 **다른 페이지(빌드)의 로그 카드**에 찍힌 한 줄이고, 그 로그는
D2 때문에 스크롤하지 않으면 접근성 트리에도 없다.

**앱 시작 경로도 같다 — 코드 추론이 아니라 실행으로 확인했다.**
`snapshot()`(864행)이 893행에서 같은 `server_rows`를 부른다는 점을 코드에서 본 뒤,
`servers\Fab-1.20.1\servermeta.json`에 BOM을 붙이고 앱을 새로 띄워
**버튼을 하나도 누르지 않은 채** 관찰했다(`s15-startup.ps1`).

| 관찰 대상 | 값 |
|---|---|
| 디스크의 서버 디렉터리 | 10개 |
| 시작 로그 1행 | `[ERROR] 서버 목록을 읽지 못했습니다: …\Fab-1.20.1\servermeta.json is not a valid servermeta.json: expected value at line 1 column 1` |
| 시작 로그 2행 | `[INFO] 루트 …\gui-qa-root · **서버 0개** · 모드팩 4개` |
| 서버 페이지 첫 페인트 | ListItem 0개, 카드 부제 `0개`, 빈 상태 `아직 서버가 없습니다. 새 서버를 만들거나 모드팩을 가져오세요.` |

즉 첫 실행부터 "루트는 정상인데 서버가 하나도 없다"고 말한다. 루트 미설정 빈 상태
(`루트 폴더를 먼저 설정하세요`)가 아니라 서버 없음 빈 상태가 뜨는 것까지 확인했다.
사용자가 "서버가 사라졌다"고 읽기 쉽다는 점에서 심각도를 높음으로 둔다.
`SheetData`에는 이미 `error-text`/`error-kind` 통로가 있으니 그쪽으로 올리는 것이
자연스러워 보인다.

측정 후 `servermeta.json`은 원상 복구했고 다시 파싱되는 것을 확인했다.

`06c-defect-empty-on-scan-error.png`, `s15-startup.log`, `s06c-refresh.log`.

### D11 — 포커스 순서가 요소 순서를 따르지 않는다 · **낮음**

DESIGN-v2 §6은 "포커스 순서 = 요소 순서"라고 적었다. 실제로는 페이지 본문이 먼저 오고,
그 다음 내비 레일, 그 다음 상단 바(테마 토글), 마지막에 준비 상태 카드의
`설정 열기`가 온다. 즉 화면에서 가장 먼저 보이는 컨트롤이 순환의 마지막이다.
또한 본문과 내비 사이에 루트 `FocusScope` 자체가 한 정지점으로 끼어 있어
(UIA에는 `Window / Nebula`로 보인다) 시각적 포커스 표시가 없는 단계가 하나 생긴다.

모두 도달은 가능하므로 낮음이다.

## 7. 검증하지 못한 것

정직하게 남긴다. 아래는 "통과"도 "실패"도 아니다.

1. **실제 스크린 리더에서의 `accessible-description`**(D8). PowerShell에서 COM
   `IUIAutomation`(`FullDescription`, 속성 30159)에 붙지 못했다. 관리형 클라이언트에는
   그 속성이 없다. NVDA/내레이터로 직접 들어 봐야 한다.
2. **Google Drive OAuth 전 과정.** 클라이언트 ID/시크릿과 계정이 없다. 반려 경로만 확인했다.
3. **가져오기 페이지의 `모드팩 폴더 열기`.** 버튼 존재만 확인했고 클릭하지 않았다
   (서버 페이지의 `폴더 열기`는 탐색기 창 생성까지 확인했다).
4. **수동 다운로드 카드.** CurseForge 배포 불가 파일이 포함된 팩을 가져오지 않아
   `<이름> 다운로드 주소` 필드와 복사 동작을 보지 못했다.
5. **`다시 시도`(retry-job) 실행.** 실패 카드에 렌더된 것은 확인했으나 누르지 않았다.
6. **`더 보기` findings 확장.** 이번 판정의 finding이 1개뿐이라 6개 초과 조건을 못 만들었다.
7. **`모션 줄이기`가 실제로 지속시간을 0으로 만드는지.** 설정 저장/복원과 스위치 상태는
   확인했지만, 켠 뒤에 애니메이션을 다시 계측하지 않았다.
8. **경고/실패 톤의 판정 배너.** `경고와 함께 통과`(strict 실패)와 `검증 실패`를
   재현하지 않았다. BASE_URL이 https라 성공 경로만 나왔다.
9. **창 리사이즈**와 최소 크기 640×800 강제.
10. **`루트 초기화`와 `폴더 만들기`.** 루트가 이미 초기화되어 있고 존재해서 두 버튼이
    렌더되지 않았다.
11. **CurseForge / Modrinth 가져오기 경로.** Prism 경로만 실행했다.
12. **토스트 3개 스택 상한.**
13. **다크/라이트 대비 수치.** 시각적으로만 확인했고 측정하지 않았다.
14. `qa-neo-bad.mrpack`이 `Modrinth`로 분류되는 것이 맞는지(내용상 "bad"인데 포맷은
    유효하다) — 포맷 판정만 관찰했고 가져오기를 시도하지 않았다.

## 9. 원본 로그를 읽을 때 주의할 점

**PASS/FAIL 개수를 결함 개수로 읽으면 안 된다. 양쪽으로 다 어긋나 있다.**

`s*.log` 전체를 합치면 `[PASS] 203`, `[FAIL] 24`, 그중 `[PASS] DEFECT:` 4줄이다. 그러나

- FAIL 쪽은 **부풀려져 있다**. 실제 제품 결함은 4줄뿐이고 나머지는 (a) 테스트 데이터
  문제로 이후 수리했거나 (b) 드라이버/판정식 자체의 버그로 뒤에 다시 측정한 것이다.
- PASS 쪽도 **부풀려져 있다**. 결함을 단정문으로 적어 둔 줄이 몇 개 있어서, 결함이
  확인되면 오히려 PASS로 찍힌다. 예:
  `[PASS] DEFECT: no error is surfaced on the page when the server scan fails`,
  `[PASS] DEFECT: the 알 수 없음 row still reports IsEnabled=True to UI Automation`.
  `DEFECT:`로 시작하는 PASS 줄은 전부 결함 확인이다.
- D2·D3·D5·D6·D9·D10·D11은 애초에 `Check`를 쓰지 않고 `Say`로 관측만 기록했으므로
  어느 쪽 집계에도 잡히지 않는다.
