# Review fixes (nebula-core) — decisions and work list

Source: read-only review of `crates/nebula-core` (17 findings). Decisions below are final; apply them as one task after the GUI wiring commit lands.

## Decisions

1. **FG2 pack.xz (blocker).** Hambugui never unpacks `.pack.xz` and verifies the SHA-256 and length of the bytes it downloads; Helios unpacks and checks the MD5 of the jar. Emitting the packed file cannot satisfy both. **Decision: FG2 emits plain jars only.** After downloading a `.pack.xz` and unpacking it with PackXZExtract, store the unpacked jar in `repo/lib` at the `.jar` Maven path, and emit the module with id `group:artifact:version[:classifier]@jar`, jar size, jar MD5/SHA256, and the jar URL. `determine_extension` still probes for `.pack.xz` remotely (that is what Forge's maven serves for old libs) but the packed file is only an intermediate in `temp/`. Documented divergence from upstream (`ForgeGradle2.resolver.ts` shipped `@jar.pack.xz`). `validate` reports any `@jar.pack.xz` id as an Error: "pack.xz artifacts cannot be verified by the Hambugui runtime". Add the gated network test `forge_1_7_10_fg2` (Forge `10.13.4.1614`, needs Java for PackXZExtract) asserting every sub-module id ends with `@jar` and that size/digests match the on-disk jar.
2. **Server id validation.** `create_server` rejects ids that are empty, contain `/`, `\`, `:`, NUL, or a `..` segment, with the message "invalid server id …: ids must be a single path segment (no / \ : or ..)". `validate` applies the same rule to `servers[].id` (Error) and also rejects empty ids.
3. **Validator parity with `hambugui-distribution`.** (a) root `version` must be a non-empty string (Error); (b) empty server/module ids are Errors; (c) `paths::clean_relative` returns `Error::UnsafePath` when the cleaned result is empty (e.g. `"."`), matching `normalize.rs`; (d) pathless `VersionManifest` ids also reject `:`; (e) `required.value`/`required.def` present but not booleans → Error. Keep the existing counts in `tests/validate.rs` valid (re-check the fixture expectations after the change; `nebula-valid.json` has `"version": "1.0.0"`).
4. **Installer GUI fallback flag.** Replace the `NEBULA_FORGE_GUI_FALLBACK` / `NEBULA_GUI` env reads inside `resolver` with `ResolveOptions { discard_output, invalidate_cache, gui_fallback: bool }`. The CLI computes `gui_fallback = env NEBULA_FORGE_GUI_FALLBACK != "0" && stdin.is_terminal()`; the GUI passes `true`. Remove the `unsafe { set_var }` from `tests/resolver_net.rs` (pass `gui_fallback: false` in options) and remove the `NEBULA_GUI` `set_var` from `gui/mod.rs` if present.
5. **Performance:** canonicalize the container once per scan (`assert_contained_in(root_real, candidate)`), single-pass `Digests { size, md5, sha1, sha256 }` used by FG2/FG3/NeoForge verification, `generate_distribution` enumerates server directories without the display counts (`list_servers` keeps counts for CLI/GUI), lazy `MANIFEST.MF` read only when `${file.jarVersion}` is present, `sort_by_cached_key` for the mod sort.
6. **Simplification:** drop `_java` from `import_modpack` (and CLI callers), drop `cwd` from `Java::run`, make the Forge-mod parser helpers `pub(crate)` and move their tests inline (`#[cfg(test)]` in `scan/forgemod.rs`), export `pub const FORGE_MOD_LIST_WARNING` from `nebula_core::server` and delete the copy in `cli.rs`, add `.read_timeout(60 s)` to the shared HTTP client, skip the Java requirement when every Forge-mod candidate is OptiFine, count only well-formed SHA-256 digests in `Report.sha256`.
7. **Thread safety:** `Box<dyn Resolver + Send>`, `Box<dyn Target + Send>`, `DownloadFn = dyn Fn(...) -> Result<()> + Send + Sync`; document that `Config::from_env()` (dotenvy) must be called once on the main thread before any worker starts (the GUI does this in `run()`).
